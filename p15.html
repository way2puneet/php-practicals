Program 7.1: GET and POST Forms Displaying Submitted Data on Another Page

Book: Program 7.1 (Chapter 7)Runs in this page
AimTo create a form using the GET method and a form using the POST method, and to display the submitted user data on another page in each case.
ConceptsCodeOutputHow it worksRun itIn XAMPPCommon mistakesViva

Concepts used

HTML form, action and method attributes, text box, drop-down list, $_GET, $_POST, $_SERVER["REQUEST_METHOD"], ??, htmlspecialchars().

Test data: Name: Aarav; course: BCA. Each form is submitted once with these values.

Logic

  1. GET version: The form in get-form.html sends the name and course to show-get.php by GET. The result page reads them from $_GET and displays them.
  2. POST version: The form in post-form.html sends the same data to show-post.php by POST. The result page confirms that the request method is POST, reads the values from $_POST and displays them.
  3. In both result pages, every value is displayed through htmlspecialchars(), and missing values are handled with ??.

Understanding the output

Both result pages display the same data, which shows that each method delivered the values to PHP correctly. The difference lies in the address bar: with GET, the name and course are visible in the URL and would be saved in the history; with POST, the URL contains no data. If the name typed is <i>Aarav</i>, both pages display the text <i>Aarav</i> exactly as typed, not an italic name, because of htmlspecialchars().

How it works

GET version: The form's action names show-get.php and its method is get, so the browser opens show-get.php?name=Aarav&course=BCA. The result page reads the two values from $_GET, using ?? so that a missing value becomes an empty string instead of producing a warning. If a name has been received, the page displays both values through htmlspecialchars(); if the page is opened directly without a query string, it displays a message asking the user to fill the form.

POST version: The second form sends the same values in the request body to show-post.php. The result page first checks $_SERVER["REQUEST_METHOD"]. When the form has been submitted, the method is POST, so the values are read from $_POST and displayed, together with the method name. If the page is opened by typing its address, the method is GET, and the page displays a different message.

The pages use the alternative syntax of the if statement, in which the opening brace is replaced by a colon and the closing brace by endif;. This form makes it easy to show or hide whole blocks of HTML between PHP tags.

Common mistakes
  • Giving the form method="post" but reading the values from $_GET, so that every value appears to be missing.
  • Omitting the name attribute of a control and giving only an id, so that its value is not sent.
  • Writing $_POST["Name"] when the control is named name.
  • Opening the result page directly and expecting it to show data.
  • Displaying $name without htmlspecialchars(), which allows HTML typed by the user to change the page.


Viva questions
Difference between GET and POST?
GET sends data in the URL (visible, limited, can be bookmarked). POST sends data in the request body (not visible in the URL, suitable for passwords and large data).
Which superglobals hold form data?
$_GET for GET forms, $_POST for POST forms, and $_REQUEST for both.
Why is htmlspecialchars() used before displaying form data?
It converts characters such as < and > into safe text, so HTML or script typed by the user cannot change the page.
