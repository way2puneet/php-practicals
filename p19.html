Create a file upload form that allows users to upload an image with size/type validation.

Program 7.3: Uploading an Image with Size and Type Validation

Book: Program 7.3 (Chapter 7)Runs in this page
AimTo write a PHP program that uploads an image file with size and type validation.
ConceptsCodeOutputHow it worksRun itIn XAMPPCommon mistakesViva

Concepts used

Upload form with multipart/form-data, $_FILES, upload error codes, size limit, getimagesize() and MIME type, safe generated file name, move_uploaded_file().

Test data: The roll numbers and files given in Table 7.9. The size limit is 500 KB, and the allowed types are JPEG and PNG images.

Logic

  1. In the form, accept a roll number and a file.
  2. In the processing page, check that the roll number has exactly four digits.
  3. Check that a file was chosen and that its error code is UPLOAD_ERR_OK.
  4. Check that its size is more than 0 and at most 500 KB.
  5. Read the actual image type with getimagesize() and check that it is JPEG or PNG.
  6. Create the name photo_ + roll number + extension of the detected type.
  7. Move the file to the uploads folder and display a message.

Understanding the output

The first output shows that a genuine PNG image within the size limit was saved under the program's own name, photo_2301.png, in the uploads folder; the size and dimensions in the message depend on the actual file chosen, so they are sample values. The third output shows that the content check rejected a text file even though its name ended in .jpg. How it works

Preparing the checks: The size limit is stored in bytes, and the array $allowedTypes maps each allowed MIME type to the extension that the program will use. The roll number and the file details are read with ??, so a missing value does not produce a warning. The if...elseif ladder then applies the checks in order, and the first failed check sets $message; the later checks are not performed.

Checking the request and the file: The ladder first confirms that the page was reached by a POST request and that the roll number has exactly four digits. It then tests the error code: no file chosen, a file too large for PHP's own limit, or any other error. Next, it compares the size with 512,000 bytes and rejects an empty file.

Checking the type: For a file that has passed these checks, getimagesize() reads the temporary file. If the result is false, the file is not an image; if its "mime" value is not a key of $allowedTypes, the image is of a type that is not allowed. In both cases, the file is rejected. A text file renamed with the extension .jpg is therefore rejected, because its content is not an image.

Saving the file: Only when every check has passed does the program build the name photo_2301.png from the validated roll number and the extension of the detected type, and move the temporary file to uploads/photo_2301.png. The success message reports the new name, the size in kilobytes and the image dimensions, which are the elements 0 and 1 of the array returned by getimagesize(). The message is displayed through htmlspecialchars().

Common mistakes
  • Omitting enctype="multipart/form-data", so that $_FILES receives no file and the program reports that no file was chosen.
  • Trusting $_FILES["photo"]["type"] or the extension of the original name instead of checking the content.
  • Saving the file under its original name, which can overwrite other files and allows unsafe names.
  • Forgetting to create the uploads folder, so that move_uploaded_file() fails.
  • Uploading a file larger than the post_max_size setting, which leaves both $_POST and $_FILES empty; the program then reports the roll-number error first.

  • GLOSSARY
  • User Input: Data supplied by a user to a web application.
  • HTML Form: A section of a web page containing controls through which data is entered and submitted.
  • Superglobal: A built-in associative array of PHP available in every part of a program.
  • $_GET: The superglobal holding values sent in the query string of the URL.
  • $_POST: The superglobal holding values sent in the body of a POST request.
  • $_FILES: The superglobal holding details of uploaded files.
  • action Attribute: The attribute of <form> that names the file receiving the data.
  • method Attribute: The attribute of <form> that decides whether data is sent by GET or POST.
  • Input Control: A form element through which the user enters or chooses a value.
  • Query String: The part of a URL after ?, carrying name-value pairs.
  • GET Method: A form method that sends data in the URL.
  • POST Method: A form method that sends data in the request body.
  • Request Body: The part of a request that carries data after its address and headers.
  • Null Coalescing Operator (??): An operator that gives a value if it exists and is not null, and a default otherwise.
  • Cross-Site Scripting (XSS): An attack in which code supplied by a user runs in a browser because it was displayed without encoding.
  • Output Escaping: Converting special HTML characters into entities before display, as done by htmlspecialchars().
  • Validation: Checking submitted data for completeness, format and limits before use.
  • Required Field: A field that must not be left empty.
  • Sticky Form: A form that keeps the values typed by the user when it is displayed again.
  • File Upload: Sending a file from the user's computer to the server through a form.
  • multipart/form-data: The form encoding that allows files to be sent with the form.
  • MIME Type: A standard label that identifies the kind of data in a file, such as image/png.
  • Temporary File: The file in which PHP stores an upload until the program moves it or ends.
  • QUESTIONS
  • Short Answer Questions
  • Q1.What is a superglobal? Name four superglobals.
  • Ans.A superglobal is a built-in associative array of PHP that is filled automatically with information about the request and is available in every part of a program without the keyword global. Four superglobals are $_GET, $_POST, $_FILES and $_SERVER.
  • Q2.What does $_GET contain? How is a value read from it?
  • Ans.$_GET contains the values sent in the query string of the URL, such as those of a form using the GET method. A value is read with the name used in the URL as the key. For the URL show-get.php?name=Aarav, $_GET["name"] gives "Aarav".
  • Q3.What does $_POST contain? Why must the form method and the superglobal agree?
  • Ans.$_POST contains the values sent in the body of a request made with the POST method. A form with method="post" fills only $_POST, so reading its values from $_GET finds nothing. The method written in the form decides which superglobal receives the data.
  • Q4.What does $_FILES contain for an uploaded file?
  • Ans.For each file control, $_FILES contains an array with the original file name (name), the type reported by the browser (type), the size in bytes (size), the temporary location on the server (tmp_name) and the error code (error). Only size, tmp_name and error are decided by PHP; the others can be changed by the user.
  • Q5.What is the purpose of the action attribute of a form? What happens if it is omitted?
  • Ans.The action attribute names the file that receives and processes the submitted data, such as action="register.php". If it is omitted, the data is sent to the same page that displays the form, which is the arrangement used by forms that validate their own data.
  • Q6.What is the purpose of the method attribute of a form?
  • Ans.The method attribute decides how the form data travels to the server: get attaches it to the URL, and post sends it in the request body. It therefore decides whether PHP reads the data from $_GET or $_POST. If the attribute is omitted, the browser uses GET.
  • Q7.State two uses and two limitations of the GET method.
  • Ans.GET is used for searches and for filtering or opening particular pages of results, because the URL can be bookmarked and repeated. Its limitations are that the data is visible in the address bar and history, so it must not carry passwords, and that the length of a URL is limited, so it cannot carry long text or files.
  • Q8.Does the POST method make form data secure? Explain.
  • Ans.No. POST keeps the data out of the address bar, history and bookmarks, but the data is not encrypted unless the website uses HTTPS, the user can see and change it with the browser's tools, and a request can be prepared without the form. Every POST value must still be validated on the server and displayed safely.
  • Q9.What is form validation? Why must it be done in PHP even if the browser checks the form?
  • Ans.Form validation is the checking of submitted data for completeness, correct format and allowed limits before it is used. Browser checks run on the user's computer and can be bypassed or switched off, so only checks performed in PHP on the server can be trusted to protect the application and its stored data.
  • Q10.Why is enctype="multipart/form-data" required in an upload form?
  • Ans.This encoding sends the form in separate parts so that the contents of a file can travel along with the ordinary fields. Without it, the browser sends only the name of the file as text, and the file never reaches the server. The form must also use method="post" and contain an <input type="file"> control.
  • Q11.What is the use of $_SERVER["REQUEST_METHOD"] in form processing?
  • Ans.It contains "GET" or "POST". A self-submitting form checks $_SERVER["REQUEST_METHOD"] == "POST" to process the data only when the form has been submitted, and to show an empty form when the page is first opened.
  • Q12.What is the null coalescing operator ??? Give an example of its use with $_POST.
  • Ans.The operator ?? gives the value on its left if it exists and is not null, and the value on its right otherwise. For example, $course = $_POST["course"] ?? ""; gives an empty string instead of an Undefined array key warning when the field was not sent.
  • Q13.Which characters are converted by htmlspecialchars(), and into what?
  • Ans.It converts & into &amp;, < into &lt;, > into &gt;, " into &quot; and ' into &#039;. The browser then displays these characters as text instead of treating them as HTML.
  • Q14.What is a sticky form?
  • Ans.A sticky form is a form that keeps the values typed by the user when it is displayed again after a validation error, through the value attribute of text boxes and selected or checked in choices, so that only the wrong fields need correction.
  • Q15.Why must the type reported in $_FILES["photo"]["type"] not be trusted? How is the real image type found?
  • Ans.The type in $_FILES is supplied by the browser, mainly from the file name, and can be changed by the user, so a renamed text file may be reported as an image. The real type is found from the content of the file with getimagesize(), which returns false for non-images and gives the actual MIME type under the key "mime".
  • Q16.What is the role of move_uploaded_file()?
  • Ans.It moves an uploaded file from PHP's temporary location to a permanent folder, such as uploads, and does so only for a file genuinely uploaded through the current request. It returns true on success; without it, the temporary file is deleted when the script ends.

  • Database Connectivity
  • Almost every practical website keeps its information in a database. The admission portal of a college keeps the records of thousands of students, an online shop keeps its products and orders, and a library keeps its books and members. The data validated by a PHP form must be stored somewhere permanent, and the stored records must later be displayed, searched and corrected through web pages.
  • We can now consider: how does a PHP program connect to a database, send instructions to it and use the records it returns? A PHP page works like a clerk at the counter of a record room. It receives a request, checks it, asks the record room for the required records or gives it a new record to keep, and returns the result to the user. In a PHP application, the record room is the MySQL database server, and the instructions are written in SQL.
  • PHP and MySQL work together through a supported database API. MySQLi opens and checks connections, creates databases and tables, executes queries, fetches result sets, inserts form submissions, displays records, updates data through forms, and supports basic database safety.


Viva questions
Which form attribute is needed for file upload?
enctype="multipart/form-data", with method="post".
What information does $_FILES give?
name, type, size, tmp_name (temporary path) and error for each uploaded file.
Why does the program check the type with getimagesize() and not with the file extension?
An extension can be renamed (fake.jpg); getimagesize() reads the real content of the file.
